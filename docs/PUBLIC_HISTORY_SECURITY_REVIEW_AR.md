## قرار الرفع

- ✅ فُحص محتوى كل Commit من الأربعة على حدة، بما فيه محتوى الملفات الجديدة والمعدلة وبيانات مؤلف/مسجل Commit والرسائل: **20 مسارًا و22 نسخة blob**. لم تُدخل هذه الدفعة SQL يحتوي سجلات عملاء أو SQLite أو `.wrangler` أو سر خدمة مؤكدًا أو بيانات اتصال R09. حذفت الدفعة تتبع 12 ملف بيانات/حالة قديمًا مع إبقائها محليًا.
- ❌ رأس الدفعة الأصلية ما زال يحتوي **خمسة روابط دعم WhatsApp قديمة** تطابق رقمًا اختاره المالك لاحقًا لاختبار R09. جميعها سابقة للدفعة وغير معدلة فيها؛ أربعة ملفات تطابق `main` أيضًا. هذا يفسر المطابقة ولا يلغي تعليمات المالك الجديدة باستبعاد الرقم بالكامل.
- ⏳ **لا رفع** للدفعة الأصلية أو للإصلاح الإضافي في هذه المرحلة؛ طلب المالك تجهيز استبعاد الرقم محليًا دون رفعه. اكتمل الإصلاح الإضافي وفحصه محليًا كما في PRIVACY_SUPPORT_FIX_AR.md؛ يبقى قرار رفعه معلقًا. لا تعديل لتاريخ Git أو Force Push أو دمج `main` أو نشر Worker أو ترحيل إنتاجي نُفذ بهذا التدقيق.

المسارات الخمسة، دون عرض قيمة الاتصال: `apps/hub/public/account-settings.js`، `apps/hub/public/recovery-ui.js`، `apps/rider/public/recovery-ui.js`، `apps/rider/public/rider-auth.js`، `apps/rider/public/rider-auth.js.backup`. المطابقات داخل `wa.me` الخاص بالدعم، وليست قائمة مستلمين جديدة أو تسريب بريد R09 من الدفعة. رغم ذلك، يجب حذف القيمة وفق اختيار المالك ومراجعة النسخ المبنية/المخزنة والتاريخ ضمن خطة التعرض.

## نطاق الفحص المستقل

فُحصت **59 Commit عامة الوصول عبر الفروع الثمانية** و**689 blob فريدة**، بإجمالي **7,479,488 بايت**: 666 نصية و23 ثنائية. أكد الفحص البعيد للفروع عدم تغيرها، ولا توجد Tags معلنة. رؤوس طلبات الدمج المغلقة الأربعة التي فحصها المسؤول مغطاة بالتاريخ المحلي؛ المراجع المخفية والنسخ المتفرعة والمخابئ ليست دليلًا على أنها نُظفت.

شمل الفحص أنماط المفاتيح الخاصة وGitHub وAWS وResend والدفع وBearer والروابط الموقعة، وتعيينات أسماء أسرار الخدمات، والملفات الاحتياطية وملفات البناء. فُكّت **أربع حاويات APK/JAR فريدة**، تشمل **54 مدخلًا و161,289 بايت بعد فك الضغط**؛ لم يُتخطّ أي مدخل لحد الحجم، ولم تظهر مطابقة سر مؤكدة داخلها. هذا فحص أنماط ومراجعة سياق، ولا يثبت غياب كل شكل محتمل من الأسرار أو كل سلوك داخل برنامج ثنائي.

### نسخة SQL والفرق بين Git وWindows

حجم blob المخزن في Git **51,155 بايت** وبصمة SHA256:

`e8a013bbbbfdaa9dddcfdffce77ef38aa2428a59febf9ef07be7a009bd34c2a7`

نسخة العمل المحلية القديمة حجمها **51,376 بايت** وبصمتها `ff455041785d0fe0e4c10d98e17a360d2c5fd27b1da0e05cbb5278d5c1482c09`. بعد تحويل نهايات CRLF إلى LF تطابق blob Git حرفيًا؛ الفرق ليس نسخة بيانات إضافية أو فسادًا، ويجب تحديد مصدر البصمة عند المقارنة.

أُعيد إنشاء SQL **داخل ذاكرة SQLite فقط** مع منع ATTACH والإضافات. يتضمن 48 جدولًا و110 عبارات INSERT. أهم السجلات الحساسة: أربعة حسابات `public_accounts`، وست جلسات `public_sessions`، وأربعة طلبات `account_recovery`، واشتراكا Push، وثلاثة ركاب وتطبيق كابتن ورحلات. لم تُكتب قيم الصفوف إلى الأدلة أو المحادثة.

تحقق شكل الأعمدة في الذاكرة: `password_hash` و`salt` للأربعة، و`token_hash` للجلسات الست، و`token_hash` و`code_hash` لطلبات الاستعادة الأربعة، كلها قيم hex بطول 64 في هذه النسخة. **هذه بصمات وليست كلمات مرور أو رموز جلسات خامًا قابلة للإعادة مباشرة**؛ تسريب بصمة كلمة المرور وملحها قد يسمح بمحاولات تخمين خارج الخدمة. لا يكفي وصف الحقول بأنها hashed لإغلاق أثر التعرض. وجدا كذلك عنوانا اشتراك Push وبيانات شخصية داخل `personal_json`؛ لا يُستنتج أن عنوان Push وحده يسمح بالإرسال دون متطلبات المزود الأخرى.

### ملفات SQLite التاريخية

أُخذت نسخ من blobs Git الأصلية مع ملفات WAL/SHM إلى مجلد خاص خارج المستودع، وفُتحت القواعد الثلاث **للقراءة فقط**. قاعدتا metadata احتوتا جدول `_cf_ALARM` فارغًا، وقاعدة D1 احتوت `d1_migrations` فارغًا. **لم يظهر صف عميل أو سر حساب في هذه اللقطة المقروءة**؛ لا يصح نسبة أسرار SQL السابقة إليها دون دليل.

محاولة deserialize الأولية للـ4096 بايت الأساسية وحدها في ذاكرة Python تعثرت بسبب وضع WAL؛ القراءة النهائية مع ملفاتها المصاحبة نجحت. لم يُعامل ذلك كفساد بيانات، ولم تتغير ملفات Git أو الإنتاج. تبقى SQLite/WAL/SHM ملفات محلية غير مناسبة للنشر حتى لو كانت هذه اللقطة فارغة.

## نتائج الأسرار والمرشحات الكاذبة

لم تظهر مطابقة مؤكدة لمفتاح خدمة قابل لإعادة الاستعمال في النطاق الممسوح. المرشح العام الوحيد في تاريخ `commerce.test.mjs` هو قيمة اختبار مقروءة اسمها `MOYASAR_SECRET_KEY` ضمن `makeEnv` ومزود fetch محاكى؛ ليس دليل مفتاح حي. وبالمثل، المطابقات الإحدى عشرة لكلمة `password` عبر سبعة ملفات اختبارات في الرأس الأصلي تخص fixtures محلية سابقة. **لا تُدوّر أسماء/قيم الاختبارات ولا تُصدر إنذار اختراق مزود اعتمادًا عليها.**

النتيجة ليست ضمانًا شاملًا: لم تُختبر صلاحية أي رمز، ولم تُقرأ أسرار Cloudflare الإنتاجية، ولم تُفحص كل نسخ Fork/CI/المخابئ أو الأجهزة. معلومات الاتصال القديمة والـSQL بيانات مكشوفة بالفعل حتى مع غياب مفتاح مزود خام مؤكد.

## خطة المعالجة دون تنفيذ إنتاجي

1. **تجميد النشر ومراجعة اللقطة الجديدة:** أُنجز استبعاد الرقم من الشجرة الحالية، وإزالة تتبع النسخة الاحتياطية القديمة مع حفظها محليًا، وإعادة بناء الأصول وفحصها المخصص. حافظ على الأربع Commits الأصلية دون تعديل تاريخها. لا ترفع أي دفعة في انتظار اعتماد الناتج الإضافي وفق طلب المالك الحالي.
2. **احتواء البيانات العامة:** جهز تغييرات إزالة ملفات SQL/حالة Wrangler من جميع القمم المتأثرة، ثم مراجعة ودمج معتمدة بشكل منفصل. قواعد `.gitignore` الحالية تمنع إعادة إضافتها لكنها لا تنظف التاريخ. يمكن للمالك تقليل جمهور المستودع مؤقتًا إذا اختار ذلك؛ تغيير الرؤية لا يسترد النسخ السابقة.
3. **تحديد الحسابات المتأثرة محليًا:** يحدد المالك إن كانت الحسابات والاشتراكات في النسخة فعلية، دون إرسال قائمة العملاء أو قيم البصمات إلى المحادثة. تُراجع تواريخ الصلاحية والحالة الحالية قراءةً قبل أي إجراء. تُسجل هوية منفذ المعالجة ونطاقها في سجل خاص.
4. **إبطال/تغيير الاعتماد المتأثر بعد اعتماد الإجراء:** للحسابات الفعلية ذات بصمات كلمات المرور المكشوفة، اعتمد إعادة تعيين آمنة لكلمات المرور وإبطال جلساتها وطلبات الاستعادة/التحديات المعنية. أعد اشتراك Push للمتأثر عند الحاجة دون افتراض كشف مفتاح VAPID الخاص. لا تُنفذ أوامر حذف أو إبطال على الإنتاج ضمن هذا التقرير.
5. **مفاتيح الخدمات إذا ثبت كشف قيمة حقيقية لاحقًا:** عطّل القيمة القديمة وولّد بديلًا لدى مزودها، وحدّث مخزن الأسرار والاعتمادات ذات الصلة، وتحقق من نجاح التبديل وإبطال القديمة. لا تنسخ القيمة إلى Git/التقارير، ولا تدور كل الخدمات دون دليل؛ تبديل إعدادات الإنتاج أو نشر نسخة Worker يحتاج موافقة مستقلة. توصي GitHub بإبطال/تدوير السر المكشوف أولًا قبل التفكير في إعادة كتابة التاريخ. [دليل GitHub الرسمي](https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/removing-sensitive-data-from-a-repository).
6. **تنظيف التاريخ — خطة فقط تتطلب موافقة صريحة:** جهز نسخة مراجعة منفصلة وخريطة لكل المسارات/الأسماء القديمة والقيم المطلوب استبعادها، وقائمة فروع/Tags/PRs المتأثرة وخطة حفظ العمل المشروع. اعرض ناتج إزالة البيانات محليًا وخريطة SHAs قبل أي اعتماد؛ لا تعِد كتابة المستودع العامل ولا تنفذ Force Push الآن. تغيير التاريخ يغير SHAs ويحتاج تنسيقًا مع أصحاب النسخ، ولا يزيل Forks أو مخابئ PR وحده؛ قد يلزم التواصل مع GitHub Support وفق شروطه بعد موافقة المالك، ولا تُرسل بيانات خامًا للدعم دون حاجة. [حدود إزالة البيانات وتنسيق النسخ](https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/removing-sensitive-data-from-a-repository).
7. **التحقق بعد المعالجة:** استنسخ الحالة المعتمدة في مجلد جديد، وافحص كل المراجع المرئية والمستندات والأصول الثابتة وAPK والتاريخ المسموح به. أعد بوابة منع البيانات/الأسرار على كل Commit مستقبلية مع مراجعة بشرية للمرشحات. احتفظ بالدليل الخاص وفق سياسة الحوادث، ولا تعِد إدخال نسخة SQL أو تاريخًا ملوثًا عبر Merge لاحق.

لم يحدث تدوير مفتاح أو إبطال جلسة أو إعادة تعيين كلمة مرور أو تغيير رؤية أو تواصل مع GitHub Support في هذا العمل. لم تُختبر OTP/رسائل فعلية ولم تُمس قاعدة الإنتاج.

## الأدلة المحلية

- `.local-verification/FOUR_COMMITS_SECURITY_GATE_PUBLIC_AUDIT.json`: فحص كل Commit من الأربعة، للمحتوى الذي أدخله فقط.
- `.local-verification/PUBLIC_HISTORY_SECURITY_EVIDENCE.json`: نطاق الفروع والتاريخ، مسارات/blobs/Commits، التثليث النهائي، وقرار عدم الرفع.
- `.local-verification/HISTORICAL_DATABASE_CLASSIFICATION.json`: أشكال الأعمدة والأعداد ونتائج SQLite للقراءة فقط، بلا قيم صفوف.
- `.local-verification/HEAD_FINDINGS_TRIAGE.json`: شرح مطابقات الدعم والـfixtures؛ قيمة الاتصال محجوبة.

أُنشئت النسخ النهائية من الأدلة عبر كتابة Node/apply_patch، ثم جرى تأكيد وجودها بعملية مستقلة؛ لم يُعتمد ظهور ملف في Python وحده بسبب اختلاف الرؤية الذي ظهر أثناء جمع الأدلة. هذا وصف لقيد الأداة المرصود، وليس تشخيصًا مؤكدًا لسبب اختفاء نسخ الجلسة السابقة.
