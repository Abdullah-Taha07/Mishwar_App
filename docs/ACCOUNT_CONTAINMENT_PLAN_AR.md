# حصر الحسابات وخطة احتواء أثر نسخة SQL القديمة

التاريخ: 16 نوفمبر 2026. المستودع يبقى **Public** كما قرر المالك؛ هذه الوثيقة لا تغير الرؤية ولا تنفذ إبطال حساب أو تغيير اعتماد إنتاجي. بيانات الهوية والاتصال وبصمات الاعتماد محصورة في manifest خاص خارج Git، ولا ترد قيمها هنا.

## ما تحقق بقراءة الإنتاج فقط

فحصت استعلامات SELECT ثابتة ذات معاملات مربوطة الهويات القديمة المحددة في SQL المسربة، ثم تطابق الاتصال وبصمات الجلسات والاستعادة وملكية Push. آخر قراءة `2026-11-16T18:57:09.235Z`، أي **21:57:09 بتوقيت الرياض**:

| النطاق | النتيجة |
|---|---|
| الحسابات في النسخة القديمة | 4 هويات `role + actor` |
| الهويات القديمة الموجودة حاليًا | **0 من 4** |
| اتصالات `role + phone` المعاد استخدامها تحت هويات مختلفة | **4 من 4** |
| عناوين البريد القديمة المعاد استخدامها تحت هوية أخرى | **1** |
| مطابقة `password_hash + salt` القديمين للحسابات المعاد إنشاؤها | **0** |
| بصمات الجلسات العامة الست القديمة في `public_sessions` أو `rider_sessions` | **0** |
| بصمات طلبات الاستعادة الأربعة القديمة المحتفظ بها | **0** |
| بصمات عنواني Push القديمين المحتفظ بها | **2**؛ أحد الربطين مطابق للقديم، والآخر تغير |

**النتيجة التنفيذية: صفر إجراء آلي آمن حاليًا على كلمات المرور أو الجلسات.** لا يجوز استبدال مفتاح الهوية المفقود برقم الهاتف ثم إبطال حساب حالي مختلف. تطابق الاتصال وحده لا يثبت أن الحساب القديم والجديد شخص واحد. ولا يجوز تصنيف البيانات بأنها تجريبية أو حقيقية من الاسم أو شكل البريد. يجب أن يؤكد المالك ملكية الحسابات وربطها عبر سجل خاص قبل أي معالجة مؤثرة.

عدم تطابق بصمة كلمة المرور والملح لا يثبت أن صاحب الحساب لم يعِد استخدام كلمة المرور الأصلية؛ تغيير الملح قد ينتج بصمة مختلفة للكلمة نفسها. غياب الجلسات والطلبات القديمة حاليًا لا يثبت عدم إساءة استخدامها سابقًا. لا توجد في هذه القراءة دلالة مؤكدة على كشف كلمة مرور خام أو مفتاح مزود أو مفتاح VAPID خاص.

لا يُحذف اشتراك Push تلقائيًا لأن `endpoint_hash` قديم: أحد الربطين تغير وقد تخصه جلسة/هوية حالية. الربط المطابق يحتاج كذلك مراجعة الملكية والحالة، ولا يثبت بمفرده أن عنوان الاشتراك قابل للاستعمال دون متطلبات التشفير/المزود الأخرى.

## الأدلة المحفوظة محليًا

manifest التعرض يحتوي الهويات والأرقام والبريد وبصمات الاعتماد القديمة، وقائمة بصمات الجلسات والاستعادة وربط Push. فحص الإنتاج يضيف تصنيفات مطابقة فقط دون نسخ أسرار Cloudflare أو رموز جلسات خامًا. الملفات الحساسة محفوظة داخل مجلد خاص تحت `D:\Mishwar_App\private-backups\account-containment-*`، ولا تُرفع إلى GitHub أو المحادثة. يحدد إيصال `.local-verification/ACCOUNT_LIVE_SCOPE_SUMMARY.json` مسار أحدث manifest دون تضمين قيم الهوية.

حُفظت كذلك قائمة موافقة خاصة تضم **4 هويات حسابات حالية مرشحة للمراجعة** و**ربطي Push**، مع هوياتها الحالية الثابتة وسبب الربط، ودون اعتماد أي إجراء. جميع علامات تأكيد الملكية معلقة، وقائمة الإجراءات الآلية فارغة. بصمة ملف المراجعة الخاص `39e9cbac8f6848b17aae8feb9496a100f412c1f599c0992009b89fa4ce381d7a`؛ إيصالها الوصفي `.local-verification/ACCOUNT_APPROVAL_CANDIDATES_SUMMARY.json`. أُعدت القائمة عند `2026-11-16T19:01:49.555Z`، أي 22:01:49 بتوقيت الرياض. هذه قراءات متتابعة وليست لقطة إنتاج ذرية؛ يعاد إثبات النطاق والشروط داخل معاملة التنفيذ بعد موافقة منفصلة.

استُخدمت ثلاث قراءات متدرجة لتفادي استنتاجات خاطئة: الهوية القديمة أولًا، ثم إعادة استخدام الاتصال، ثم مطابقة بصمة الاعتماد وربط Push. لم تنفذ الأداة تصديرًا جديدًا أو UPDATE/DELETE/INSERT بعيدًا، ولم ترسل بريدًا أو SMS.

## الخطة المستهدفة قبل أي موافقة تنفيذ

1. **اعتماد ربط المالك:** يراجع المالك قائمة الهويات القديمة والحسابات الحالية خارج المحادثة، ويحدد إن كانت تخص أشخاصًا فعليين ويقدم دليل الربط بالحساب الحالي. لا تدرج جهة اتصال من النسخة القديمة تلقائيًا ضمن أهداف الإبطال.
2. **تثبيت النطاق الخاص:** يسجل لكل هدف مصادق عليه `role + actor` الحاليان وبصمة الاعتماد المتوقعة ومرجع الموافقة. تكون أهداف Push قائمة مستقلة تشمل بصمة endpoint والربط المتوقع قبل أي حذف، مع مراجعة الربط الذي تغير. لا تستعمل قائمة عامة لكل الحسابات أو لكل من يشترك بالرقم.
3. **معالجة كلمة المرور بملكية مثبتة:** يستخدم صاحب الحساب تدفق إعادة التعيين المعتمد بعد إثبات ملكية قناة حقيقية، ويختار كلمة مروره بنفسه في واجهة آمنة. لا كلمة مرور مشتركة أو افتراضية، ولا تعيين قيمة عشوائية مجهولة للمالك يتركه خارج الحساب. البريد غير مهيأ حاليًا وR09 الخارجي غير مغلق؛ لا يُرسل رابط وهمي ولا يفترض وصوله. إذا تعذر توفير إثبات/قناة آمنة، تبقى مرحلة تغيير كلمة المرور متوقفة حتى اعتماد الإجراء.
4. **إبطال مستهدف بعد التحقق:** قبل تنفيذ معتمد، تُقرأ الهوية وبصمة الاعتماد وملكية الجلسات/الرموز من جديد، وتُثبت نسخة خاصة وخطة تواصل مع أصحاب الأهداف. بعد إتمام إعادة التعيين يرفض النظام كلمة المرور السابقة، وتُبطل جلسات الحساب المستهدف والرموز القديمة وطلبات الاستعادة/التغيير/OTP ذات الصلة فقط. أي اختلاف في الهوية أو البصمة أو الربط المتوقع يوقف الدفعة كلها لإعادة المراجعة؛ لا يوسع النطاق تلقائيًا.
5. **السباقات والطلبات الجارية:** لا يكفي فحص قائمة قديمة قبل التنفيذ؛ يتطلب الانتقال معاملة ذرية وحارس اعتماد معاد فحصه عند الالتزام، وتشغيلًا متوافقًا مع آلية تجميد/تصريف الكتابة المعتمدة. جلسة أنشئت أثناء انتظار رد المزود لا تُترك صالحة بعد إعلان الإبطال. لا يسمح سجل الحادث أو إعادة تشغيله بإعادة إنشاء جلسة/رمز أُبطل.
6. **الاشتراكات والبيانات الشخصية:** يعاد اشتراك Push للأهداف المعتمدة عند الحاجة دون حذف اشتراك صاحب هوية مختلفة. تُراجع السجلات وأصول الهوية/الرحلات التي كُشفت، وتوضع خطة احتواء وإخطار ملائمة بعد تحديد الحسابات الفعلية؛ لا يعرض التقرير قائمة العملاء أو السجلات الخام.
7. **المراقبة والتراجع:** نجاح الاحتواء لا يعني أن نسخ Git/المخابئ اختفت. لا يُسترجع بعد الإبطال سر أو رمز جلسة أو كلمة مرور قديمة من backup. تصحيح هدف خاطئ يكون بإعادة تحقق المالك وإنشاء جلسة/اعتماد جديدين، لا إحياء بيانات التعرض. استعادة D1 كاملة قد تعيد الأسرار والطلبات القديمة، ولذلك تحتاج قرارًا منفصلًا يحفظ أثر الإبطال ويمنع إعادة إدخاله.

## أداة التجربة المحلية وحدودها

`scripts/security/account-containment.mjs` مكتبة **محلية فقط**؛ لا تحتوي اتصال Cloudflare أو أمر تغيير إنتاجي. تعيد SQL إلى قاعدة SQLite جديدة مع منع ATTACH والإضافات، وتستعمل manifest خاصًا واختيارًا صريحًا من الهويات المعرضة. لا تقبل هدفًا خارج القائمة أو تكرار هدف أو اختيارًا فارغًا، ولا تستبدل هوية مفقودة برقم الهاتف.

بيئة الأداة المحلية المعتمدة Node 26.13 التي تدعم SQLite authorizer وdefensive mode. ليست مطلوبة لتشغيل واجهات التطبيق، ولم تُوسع صلاحيات أي بيئة منشورة.

في المعاملة المحلية تعاد مطابقة الهاتف وبصمة الاعتماد والملح لجميع الأهداف **قبل أي أثر**. إذا تغير هدف واحد تُلغى الدفعة كلها. تُحذف جلسات الأهداف وإشعارات الأجهزة المرتبطة بها بالدور الصحيح، وتُقصّر صلاحية رموز الاستعادة والبريد وOTP والتغييرات والتحديات القديمة ذات الصلة. لا تتغير كلمات المرور أو بيانات الحساب أو المحفظة أو أي هوية غير محددة. حذف Push المحتفظ به بسبب التطابق التاريخي فقط غير موجود بالأداة، لأنه يحتاج قائمة ربط وموافقة منفصلة.

لا تنفذ الأداة تغيير كلمة المرور؛ مرحلة كلمة المرور تتطلب تدفق إثبات المالك أعلاه. هذه ليست أداة آلية لفرض إعادة تعيين على الإنتاج أو دليلاً على إغلاق الحادث.
