# تثبيت مشوار على آيفون وأندرويد — حزمة تطوير آمنة

- أندرويد: APK مثبت داخل Android WebView أو PWA من Chrome. نسخ APK المنشأة في GitHub Actions حاليًا Debug وليست مناسبة للتوزيع العام أو التحديث المستمر لأن التوقيع غير ثابت.
- آيفون: PWA من Safari عبر «مشاركة > إضافة إلى الشاشة الرئيسية». الأيقونة مستقلة ومظهر التطبيق standalone. لا يمكن تثبيت APK على iOS.
- لا يوجد IPA موقّع في هذه الحزمة. تطبيق iOS أصلي وتوزيعه عبر TestFlight/App Store يحتاج إعداد Xcode وشهادات توقيع وعضوية Apple Developer Program.
- إشعارات Web Push على iPhone ممكنة في iOS 16.4+ لتطبيقات الشاشة الرئيسية إذا ضبطت الخدمة والأذونات، لكنها ليست مضمونة دون اختبار حقيقي. تتبع GPS بالخلفية غير مكافئ للتطبيق الأصلي.
- ملفات manifest.webmanifest لكل تطبيق كانت تضم display:standalone وicons ومجال خاص، ولذلك التعديل يركز على صفحات التثبيت والمشاركة وحالة التطبيق.
- رابط APK المباشر مُعطَّل حتى تحديد HTTPS URL موثوق لإصدار موقّع بمفتاح دائم. عدم إظهار زر وهمي حماية للمستخدم من نسخ Debug المؤقتة.
- هذه الحزمة لا تنشر main أو Vercel أو Cloudflare ولا تغيّر قاعدة D1. بعد الدمج يجب نشر صفحات الويب يدويًا ثم اختبار iPhone Safari وAndroid Chrome.

## اختبار القبول
1. فتح رابط /install.html لكل دور من آيفون Safari ثم Add to Home Screen والتحقق من الأيقونة والمظهر المستقل.
2. فتح الرابط على Android Chrome وظهور خيار Install عند استيفاء شروط المتصفح، أو ظهور التعليمات الصحيحة.
3. التأكد من أن زر مشاركة الرابط يفتح قائمة النظام إن دعمها المتصفح؛ وإلا يوضح سبب عدم توافر المشاركة بدلاً من الادعاء بأنه شارك.
4. التأكد من أن نسخ الرابط ينسخه فعلًا وأن روابط التطبيقات الثلاثة لا تختلط.
5. تشغيل الجلسة، GPS، وتدفق المشوار؛ لا تستنتج نجاحها من تثبيت PWA فقط.
6. اختبار Notifications على iOS المثبت وبموافقة المستخدم فقط؛ لا تعتمد على GPS بالخلفية للكابتن بدون تطوير native حقيقي.
