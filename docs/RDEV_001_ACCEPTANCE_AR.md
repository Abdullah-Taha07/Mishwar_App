## بوابة تشغيل القبول الحقيقي — غير منفذة

لا يبدأ التشغيل حتى تتوافر جميع العناصر التالية ويُسجل إثباتها:

1. روابط عملاء الاختبار المعتمدة وتوجيه بواباتها إلى Worker staging، مع SHA العامل وإثبات عدم إحالة أي API إلى الإنتاج. لا يُنشأ نشر staging ضمن التفويض الحالي الذي يمنع نشر Cloudflare/Vercel.
2. إعدادات التشغيل الفعلية وموارد D1/R2 المنفصلة، ومفاتيح خدمات ومصادقة وحسابات اختبار مستقلة. تحديد موارد الاتصال من runtime العامل، لا من Base config فقط.
3. مفتاح TomTom مخصص للاختبار مع موافقة استخدامه وحدود الحصة والقيود، وتسليمه عبر موضع سري محلي أو اسم Secret؛ لا يوضع في التوثيق أو Git أو السجلات. مفتاح متصفح محدود منفصل إذا تطلبت الخريطة ذلك. لا تُستخدم مفاتيح الإنتاج كبديل.
4. اعتماد قائمة المواقع العامة المرجعية وحدود الخطأ المقبولة لكل نوع قبل التشغيل. لا تستخدم عناوين أو حسابات العملاء أو بياناتهم، ولا تختَر حد الخطأ بعد رؤية النتائج.
5. ميزانية طلبات وخطة أدلة منقحة، وإثبات قراءة لحالة قاعدة الاختبار قبل التشغيل وبعده إذا كانت القراءة البعيدة معتمدة. لا تشغيل ترحيلات أو تنظيف أو حذف بيانات ضمن هذا القبول.

## سيناريوهات القبول المجهزة

كل ما يلي **غير منفذ على خدمة حقيقية**؛ جدول الحالات يُملأ بعد اجتياز بوابة العزل. الخادم والمتصفح يعملان من النسخة نفسها، ويُسجل لكل حالة وقت التنفيذ وSHA ومعرّف الطلب وحالة HTTP.

| الحالة | الإجراء | معيار القبول والدليل |
|---|---|---|
| البحث المرجعي | ستة استعلامات معتمدة: شارع وحي ومعلم بالعربية والإنجليزية | إحداثيات صالحة، ونوع/اسم/منطقة مناسبة، وقياس فرق الموقع عن المرجع المعتمد؛ لا اعتبار ترتيب نتائج البديل إثبات دقة |
| العنوان العكسي | Reverse لانطلاق ووجهة مرجعيين | عنوان متوافق مع المرجع والإحداثيات؛ لا قيمة افتراضية مختلقة عند الفشل |
| اختيار النتائج | اختر الانطلاق والوجهة عبر الواجهة الفعلية | الإحداثيات المختارة نفسها تنتقل إلى طلب الطريق والعلامات وquote؛ لا حقن لحالة العميل |
| تبديل البحث | غيّر النص سريعًا أثناء طلب ثم امسحه وأعد البحث | لا تُعرض نتيجة الطلب السابق، ولا يبقى مسار أو سعر لنقاط أُبطلت |
| الطريق والمحطة | احسب طريق قيادة، غيّر الوجهة ثم أضف محطة | عددlegs يساوي عددالنقاط−1، أجزاء متصلة، وأطراف قريبة من المطلوب وفق سياسة المصدر الحالية؛ تُراجع صحة الطريق المرجعي أيضًا |
| القياسات والتسعير | قارن رد المزود المنقح والخريطة والملخص والسعر | هندسة مرسومة مطابقة للرد المقبول، مسافة/مدة موجبتان ومتحققتان، تحويل الوحدات صحيح، والتعرفة على snapshot نفسه دون جمع delay مرتين |
| المرور | راجع حقول المرور وطلب `traffic=true` والوقت | 0≤delay≤duration؛ لا تدّع ازدحامًا ميدانيًا من delay=0 أو من مجرد توفر الحقل |
| الانقطاع والتعافي | اقطع شبكة متصفح الاختبار ثم أعدها | لا يظهر سعر/طريق قديم كأنه صالح؛ إعادة المحاولة تتعافى. هذا ليس إثباتًا لفشل TomTom نفسه |
| آثار البيانات | لا تضغط زر الحجز؛ قارن عدادات الاختبار قبل/بعد | فرق الرحلات والحجوزات وحركات المحفظة والتسويات=0؛ توثيق أي quote اختباري منفصلًا |

تحقق الكود الحالي يقبل تقريب أطراف الطريق حتى2000م كحد snap وقائي، لكنه **ليس معيار اعتماد دقة العنوان أو الموقع التجاري**؛ مرجع المواقع وحدود دقته يُعتمدان مستقلين. يجب أن تبقى كل leg متصلة بالتالية، وتطابق نقاط الطلب بما فيها المحطات. المسافة الهوائية لاقتراح البحث لا تُعرض كمسافة قيادة، ولا يُستبدل فشل الطريق بخط مستقيم وسعر موثوق ظاهريًا.

أخطاء429/المهلة/5xx تُسجل عند وقوعها الطبيعي؛ لا تُستنزف الحصة أو تُعطل الخدمة لصنعها. إذا لم تقع، تبقى **NOT OBSERVED LIVE**، ويُحال إثبات آلية معالجتها إلى الاختبارات المحلية القائمة دون الادعاء بنجاح اختبار خطأ حقيقي. لا يُخلط رد fixture بالرد الفعلي في الأدلة أو عدد اختبارات القبول الحقيقي.
