# RIDER-014.001 — تمييز فروع المكان المتشابهة في المفضلة

الأساس المعتمد: `6727303f56b06e1379fb080656eee035988394f7`، آخر RIDER-013 المكتملة. جُلب أحدث `dev/mishwar-shared` وطابقه؛ العمل والإصلاح على الفرع نفسه، دون تغيير main أو إعادة المراحل السابقة.

**النتيجة: RIDER-014.001 مكتملة ضمن القبول المحلي المحدد؛ RIDER-014 جزئية.** لم تُختبر دقة TomTom الحقيقية أو مساراته وزحامه ميدانيًا، ولم يُشغَّل Staging بعيد أو نشر أو D1/R2 بعيدان.

## المشكلة الواحدة وإثباتها

كانت مقارنة المفضلة في `search-ui.js` تعتمد الاسم وتقارب خط العرض فقط، وتتجاهل خط الطول. نتيجتان بالاسم وخط العرض نفسيهما لكن بموقعين شرقي وغربي مختلفين تبقيان نتيجتين منفصلتين في البحث، ومع ذلك كان حفظ الأولى يجعل قلب الثانية يبدو محفوظًا؛ والضغط على الثانية قد يحذف الأولى بدل حفظ موقع مستقل.

أُعيد إنتاج العيب قبل الإصلاح عبر اختبارات تنفذ مكوّن البحث الحقيقي: **3 فاشلة و2 ناجحة من5**. أثبت Edge كذلك ظهور القلبين محفوظين بعد حفظA فقط، وفشل سيناريو القبول قبل الإصلاح عند هذا الشرط. السجلات والصورة الحمراء محفوظة؛ لم يُعد وصفها كنجاح.

أضيفت مقارنة واحدة `sameFavoritePlace` تشمل الاسم و`lat` و`lng`، وتُستخدم في عرض القلب والتحقق من الوجود والحذف. بقي هامش التقارب القائم **أقل من0.001 درجة لكل محور** دون تغيير؛ ليس هذا مقدارًا ثابتًا بالأمتار أو هوية POI عالمية. لم يتغير ترتيب البحث أو cache أو نطاق المدينة أو سياسة المسار والتسعير أو الحسابات.

## العزل والمزود المعلن

الاختبارات البرمجية تنفذ `search-ui.js` و`account-context.js` وسياسة الموقع الفعلية داخل VM مع DOM وتخزين اختبار. قبول Edge يستخدم ملفات الراكب المبنية محليًا على loopback فقط، وخادم RIDER-013 المعزول ببوابة وWorker حقيقيين وSQLite جديدة بالذاكرة؛ حساب الاختبار وOTP والكابتن صناعية ومعلنة.

**استجابة `/api/places` في هذا السيناريو بديل محلي معلن بصيغة GeoJSON، وليست طلب TomTom فعليًا ولا اختبارًا لمحوّل استجابة TomTom.** يُنشئ البديل نتيجتين اصطناعيتين بالاسم نفسه: `(24.7136,46.6753)` و`(24.7136,46.8753)`. تمر الإحداثيات عبر التحويل والترتيب والعرض واختيار النتيجة في كود الواجهة الحقيقي. تُستبدل الخطوط وبلاطات الخريطة محليًا، ويُرفض أي اتصال متصفح خارجي غير متوقع. لا تُقرأ مفاتيح إنتاج أو ملفات أسرار لتشغيل الاختبار.

الاختيار في المتصفح نقرات CDP فعلية على الهاتف المحاكى390×844؛ لا يُحقن `pickupPoint` أو نتائج المحرر أو حالة التطبيق. يُقرأ التخزين والإحداثيان بعد النقر للتحقق فقط. يثبت السيناريو:

1. حفظA لا يملأ قلبB ولا يغير إحداثياتA.
2. حفظB يبقي المفضّلتين مستقلتين.
3. إزالةB تُبقيA، وتستمر الهوية الصحيحة بعد إغلاق البحث وإعادة فتحه.
4. اختيارB كنقطة انطلاق يحافظ على إحداثييB الفعليين.
5. لا يُرسل طلب `live_quote/live_book` ولا تُختلق مدة أو مسافة قيادة لهذا السيناريو الخاص بالبحث. المسافة المكانية في اقتراحات البحث ليست دليل قبول مسار قيادة أو زحام.
