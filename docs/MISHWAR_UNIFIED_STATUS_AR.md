## حدود الثقة للاتصال

الراكب لا يمرر هوية HTTP أو IP يقدمه العميل. Node يعتمد `x-vercel-forwarded-for` فقط داخل runtime يحدد `VERCEL=1`، وخارجه يعتمد socket. Cloudflare المباشر يحتاج metadata من runtime؛ من دون مصدر IP موثوق تفشل العمليات العامة المحدودة بـ503 بدل جمع الجميع في unknown. حسابات تسجيل الدخول والمسافة الموثقة لها حصص منفصلة؛ الحصة الشبكية العامة تبقى حزام حماية من الإساءة، وحصة الضيوف مشتركة بطبيعتها عندما لا توجد هوية موثقة.

المراجع: [رؤوس Vercel](https://vercel.com/docs/headers/request-headers)، [رؤوس Cloudflare وحدود Worker subrequests](https://developers.cloudflare.com/fundamentals/reference/http-headers/). إعادة الكتابة عبر Vercel قد تجعل عنوان الشبكة على Cloudflare عنوان الوكيل؛ لذلك يجب فحص هذا المسار على staging، ولا نثق بـXFF يرسله العميل. لم تُضبط مفاتيح أو أصول إنتاج. `PUBLIC_API_ORIGINS` عند الحاجة قائمة HTTPS دقيقة، وليست wildcard.
