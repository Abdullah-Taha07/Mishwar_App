# سجل أعمال راكب مشوار — RBUG / RDEV / RQA

**الاعتماد:** 20 نوفمبر2026، بتوجيه المستخدم. المستودع `Abdullah-Taha07/Mishwar_App`، وفرع المشاركة الوحيد `dev/mishwar-shared`. هذا الملف مرجع التصنيف والترقيم للمهام الجديدة؛ يبقى سجل RIDER القديم وأسماء ملفاته وتقاريره والـCommits دون إعادة ترقيم أو إعادة تنفيذ.

## نظام الترقيم المعتمد

| المسار | الغرض | صيغة المعرّف |
|---|---|---|
| RBUG | إصلاح الأخطاء البرمجية | `RBUG-NNN` |
| RDEV | تطوير الوظائف والتحسينات | `RDEV-NNN` |
| RQA | اختبارات الجودة والتحقق والاعتماد | `RQA-NNN` |

لكل مسار تسلسل مستقل من ثلاثة أرقام. لا تُستخدم أرقام RIDER القديمة لمهام جديدة، ولا تُنشأ تقسيمات مثل `.001` أو`.002`. يُحتفظ بـ`RIDER-014.001` كما هو **مرجعًا تاريخيًا فقط**.

الأرقام الجديدة الصريحة المعتمدة حتى الآن هي `RBUG-001` و`RDEV-001` و`RDEV-002` و`RQA-001`. لا تمنح مراجعة السجل التاريخي أرقامًا جديدة بأثر رجعي؛ يبقى الوصف «تاريخي» عندما لم يعتمد المستخدم معرّفًا محددًا. العمل المختلط يمكن أن يحوي إصلاحًا واختبارًا داخل نطاقه، دون تحويل كل جزء إلى مهمة مرقمة مستقلة.

- آخر Commit كود معتمد مرفوع قبل توثيق التصنيف: `7e7c0064b6af4d83ae75e344866209bcb0db32d6`.

## قواعد متابعة السجل

1. تُراجع المهام المكتملة والأدلة قبل فتح عمل جديد؛ لا يعاد العمل المكتمل لمجرد تغيير اسمه.
2. أي مهمة جديدة تحتاج نوعًا واحدًا ومعرّفًا مستقلًا ونطاقًا ومعايير قبول ودليل Commit، وفق طلب معتمد؛ لا بدء تلقائي لأي عمل من وجوده في السجل.
3. «مكتملة» تخص نطاق القبول الموثق. لا تُحوَّل محاكاة مزود أو نتيجة محلية إلى اعتماد خدمة فعلية أو جاهزية تجارية.
4. يبقى [سجل التقدم](RIDER_PROGRESS.md) و[ملف الاستئناف](RIDER_RESUME.md) محتفظين بنصوصهما التاريخية، ويحيلان إلى هذا الملف للترقيم الجديد.
5. مهمة اعتماد السجل **تنظيم وتوثيق فقط**: ملفاتها `RIDER_WORK_REGISTER.md` و`RIDER_PROGRESS.md` و`RIDER_RESUME.md`. لا بدء RDEV-001 أو تطوير برمجي جديد أو تغييرmain أو نشر أو تغيير قاعدة بيانات.
